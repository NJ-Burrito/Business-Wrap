# 07 · التحديثات للإنسان ولوكيله (عربي) — الملف المقابل: 07-updates.md

**الخلاصة:** مصدر إصدارات واحد (إصدارات GitHub في المستودع الخاص)، وفحص واحد مخزن مؤقتا (طلب واحد في اليوم على الأكثر)، وسطر واحد للمستخدم، ولا يثبت شيء دون موافقته. المبدأ نفسه المتبع في محدث QA Wrap، يصل إلى الشخص في المحرر والطرفية، وإلى الوكيل عبر SKILL.md وAGENTS.md وMCP وخطاف اختياري.

## مصدر الإصدارات
| الجزء | الوظيفة |
|---|---|
| `update/source.json` | المستودع الذي يقرؤه الفحص |
| `update/core.mjs` | مقارنة الإصدارات رقميا، ورفض المسودات والإصدارات التجريبية، وقبول روابط تنزيل هذا المستودع فقط، والفحص مع ETag والتراجع عند حد المعدل، وتحليل الملاحظات |
| `update/check.mjs` | الرمز (المتغير `BW_UPDATE_TOKEN` أو `.local/update-token` أو `gh auth token`)، والتخزين اليومي في `.local/update-state.json`، والإعدادات في `.local/update.json` (‏`check` و`hook`)، والسطر الواحد بالعربية أو الإنجليزية |
| `.github/workflows/release.yml` | وسم `vX.Y.Z` ← فحص الإصدار ← ملاحظات مقتطعة من سجل التغييرات ← ملف `business-wrap-X.Y.Z.zip` ومعه `.sha256` ← إصدار |
| `update/version-sync.mjs` | فحص في التكامل المستمر: الحزمة والإضافة والسوق وسجل MCP وSmithery وملفات README وسجل التغييرات على إصدار واحد |

المستودع خاص: دون رمز يجيب الفحص بهدوء «تعذر الفحص». الرمز يقرأ ويرسل في ترويسة Bearer، ولا يطبع أبدا ولا تخزنه الأداة.

## من يرى ماذا
| الجمهور | القناة | السلوك |
|---|---|---|
| الشخص في المحرر | `editor/update.js` (وحدة مستقلة، ونقطة تركيب واحدة في `engine/build-editor.mjs`) | «الجديد» مرة واحدة بعد التحديث؛ وبطاقة «يتوفر تحديث» عند التشغيل عبر `engine/serve.mjs` فقط، بأزرار «حدث الآن» و«لاحقا» و«إيقاف»؛ متحركة وتحترم تقليل الحركة؛ ولا تطبع ولا تحفظ في «حفظ HTML» |
| الشخص في الطرفية | `npx business-wrap update --check` | سطر واحد وثلاث نقاط؛ و`--apply --yes`؛ و`--notes`؛ و`--off` و`--on` |
| الوكيل مع المهارة | قسم «First: check for an update» في SKILL.md | يفحص في بداية المهمة، ويخبر المستخدم بسطر، ويعرض الأمر، ولا يحدث تلقائيا |
| ‏Codex وCursor وGemini CLI | `AGENTS.md` | التعليمات نفسها |
| أي عميل MCP | خادم MCP | `update_available` في تعليمات التهيئة وفي أول نتيجة أداة في الجلسة؛ و`check_update`؛ و`apply_update` يرفض دون `confirm: true` |
| إضافة Claude Code | `/plugin update` و`hooks/hooks.json` | إصدار السوق هو القناة؛ وخطاف بدء الجلسة يطبع سطرا فقط بعد `--enable-hook` (معطل افتراضيا) ويستخدم التخزين اليومي |

## تطبيق التحديث
- نسخة git: يرفض إن وجدت تغييرات محلية على ملفات متتبعة، ثم يجلب ويتقدم للأمام؛ وملفات المستخدم مستثناة من git.
- تثبيت من ملف مضغوط: ينزل ملف الإصدار (بالرمز للمستودع الخاص)، ويتحقق من SHA-256، ويحتفظ بنسخة احتياطية **واحدة**، ويستبدل ملفات المنتج، ويستعيد النسخة عند أي فشل.
- لا يمس أبدا: `.local` و`design/custom` و`logos` و`fonts/custom` و`drafts` و`out` و`.git` و`node_modules`.
- ثم ترحل بيانات المستخدم بالمحرك **الجديد** (ملفات `*.edits.json` من الإصدار 0 إلى 1).

## ملاحظات إصدار لجمهورين
كل قسم في سجل التغييرات ثنائي اللغة، وقد يحمل `### Migration notes / ملاحظات الترحيل`: الأوامر والمخططات التي تغيرت والتغييرات الكاسرة، مكتوبة للوكيل. ويفصلها الفحص: النقاط البارزة للشخص، وملاحظات الترحيل للوكيل.

## بوابة المخطط
يرفض ملف التعديلات الذي يحمل `version` أحدث من المحرك («حدث Business-Wrap أولا»)، ويرحل ملف الإصدار 0. ولا يحول الوكيل الملف إلى إصدار أقدم، ولا يطبق تعليمات قديمة على مخطط جديد دون الترحيل الذي تصفه الملاحظات.

## ما نقل من QA Wrap
الملفات والأسطر المنقولة مذكورة في الملف المقابل بالإنجليزية، قسم «Mirrored from QA Wrap».
