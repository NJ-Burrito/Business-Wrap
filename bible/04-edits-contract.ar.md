# 04 · عقد التعديلات (عربي) — الملف المقابل: 04-edits-contract.md

**الخلاصة:** لا يغير المحرر ملف JSON للوثيقة أبدا. بل يكتب `edits.json`: قائمة مرتبة من العمليات على مؤشرات JSON وفق RFC 6901. إعادة تطبيق العمليات على الوثيقة الأساسية (المطابقة بقيمة `baseHash`) تعطي الوثيقة المعدلة. المخطط: `contracts/edits.schema.json` (الإصدار 1)، وقد اعتمده محرك المحرر.

## الغلاف
| الحقل | المعنى |
|---|---|
| `version` | `1` |
| `document` | معرف الوثيقة |
| `baseHash` | `sha256:<hex>` لبايتات ملف JSON الأساسي؛ وترفض إعادة التطبيق عند عدم التطابق |
| `locale` | `ar` (من اليمين إلى اليسار) أو `en` (من اليسار إلى اليمين): النسخة المعدلة |
| `createdAt` و`author` | اختياريان؛ والمؤلف أحرف أولى أو نص حر، لا بريد ولا رقم هوية أبدا |
| `theme` | تجاوزات اختيارية للرموز بمسار DTCG (`"color.role.primary": "#1f6f5c"`) |
| `ops[]` | التعديلات بترتيبها |

## العمليات
| العملية | الحقول | الاستخدام |
|---|---|---|
| `setText` | `path` و`value` و`old` | تغيير نص طرفي: فقرة أو خلية أو عنوان أو تسمية |
| `replace` | `path` و`value` و`old` | استبدال عقدة كاملة |
| `insert` | `path` (رقم موضع أو `-`) و`value` | إضافة كتلة أو صف أو فقرة أو قصة |
| `delete` | `path` و`old` | حذف عنصر؛ ويحفظه `old` للتراجع |
| `move` | `from` و`path` | إعادة الترتيب بالسحب أو بلوحة المفاتيح (بدلالة النقل في JSON Patch) |
| `duplicate` | `path` و`to` (افتراضيا: بعده مباشرة) | نسخ عنصر |

تحل المؤشرات على الحالة بعد كل العمليات السابقة. ويجعل `old` كل عملية قابلة للعكس، وهذا هو سجل التراجع.

## القواعد
1. **عبر العمليات فقط.** الحفظ = كتابة `edits.json`؛ والتصدير = إعادة التطبيق ثم العرض. التعديل اليدوي على ملف JSON للوثيقة يضيع عند إعادة بناء المرحلة التالية.
2. **فحص التعارض:** عملية `setText` تختلف قيمتها الحالية عن `old` تعارض؛ يعرض المحرر القيمتين ويسأل، ولا يكتب فوقها بصمت.
3. **إعادة الترقيم** بعد الإدراج أو الحذف أو النقل يتولاها محرك العرض من الموضع، ولا تخزن في العمليات.
4. **اللصق نص خام.**
5. **التعديلات المتكررة خلل في المنبع.** إذا ظهرت العملية نفسها في عدة وثائق، فأصلح قاعدة المصدر؛ فملف التعديلات لحكم إنساني على وثيقة واحدة.
6. **لا أسرار ولا علامة مائية:** ملف التعديلات مخرج؛ لا يحمل بيانات دخول ولا بيانات شخصية سوى الأحرف الأولى، ولا العلامة المائية للمحرر أبدا.

## مثال
```json
{ "version": 1, "document": "SAMPLE-001", "baseHash": "sha256:<64 hex>", "locale": "ar",
  "ops": [
    { "op": "setText", "path": "/chapters/0/sections/0/blocks/0/paragraphs/0", "value": "صياغة جديدة.", "old": "صياغة قديمة." },
    { "op": "move", "from": "/chapters/1/sections/0/blocks/2", "path": "/chapters/1/sections/0/blocks/0" } ] }
```

## صادرات المحرر غير ملف التعديلات الواحد (`contracts/wrappers.schema.json`)
| `kind` | المحتوى | ملاحظات |
|---|---|---|
| `bw-edits-bundle` | `{kind, version: 1, createdAt, files: [edits v1…]}` | «تصدير التعديلات» لخدمة واحدة (بالنسختين) أو «كل الخدمات» |
| `bw-design-pack` | السمة المبنية (`name, fonts, sizes, vars, brand, logos`) مع النوع والإصدار | بالشكل نفسه الذي يكتبه `design/build.py` في `theme.json`؛ والاستيراد لا يقبل إلا قيما بشكل الرموز وروابط شعارات من نوع data أو نسبية |
| `bw-comments` | `{kind, version: 1, comments: [{id, path, text, at, service, locale}]}` | التعليقات لا تطبع أبدا ولا تدخل ملف JSON للوثيقة |
| `bw-change-log` | `{kind, version: 1, service, locale, baseHash, exportedAt, changes: [العملية مع حالتها], versions: [{name, at, ops}]}` | الحالة `pending` أو `approved` أو `rejected`؛ والعمليات المرفوضة تخرج من الوثيقة ومن كل تصدير |

ترحل الملفات الأقدم عند الاستيراد (`migrate()`: من مصفوفة عمليات مجردة في الإصدار 0 إلى الإصدار 1).

## إضافات المحرر إلى ملف JSON للوثيقة
- يجوز أن تحمل أي كتلة `layout: {breakBefore?: bool, keepNext?: bool}` (ضوابط فواصل الصفحات: «صفحة جديدة قبلها» و«إبقاء مع ما يليها»). تضبط بعملية `replace` على `<block>/layout`، وتنعكس على النسختين.
- كتلة الصورة `{kind: "shots", caption, images: ["data:image/png|jpeg|svg+xml;base64,…"], width: 10–100}`؛ والعرض نسبة مئوية من عرض السطر البالغ 150 مم. ويضع DOCX صور PNG وJPEG، ويتخطى صور SVG.
- تعديل جملة هدف القصة المركبة يكتب في الحقل `goal` للقصة.

## زوج النسختين العربية والإنجليزية
- النسختان وحدة واحدة. التعديل البنيوي (نقل، حذف، إدراج، تكرار، صف أو عمود، ضوابط فواصل الصفحات) الذي يُجرى وخانة **على النسختين** مفعّلة (وهي مفعّلة افتراضياً) يُطبّق على النسخة الأخرى عند المؤشر نفسه؛ ويبقى ملف التعديلات يسجّل كل نسخة على حدة (`locale` و`baseHash`).
- تعديلات النص تخص كل نسخة: تعديل حقل يُعلّم الحقل نفسه في النسخة الأخرى بـ**يحتاج تحديثاً** إلى أن يُعدّل هناك أيضاً.
- قبل التصدير يجب ألا تُظهر لوحة **فحص** سطر «النسختان غير متطابقتين في البنية» (الفصول والأقسام وأنواع الكتل وأحجام الجداول نفسها في النسختين)، وألا يبقى حقل يحتاج تحديثاً.
- استيراد ملف تمسّ تعديلاته البنيوية الكتلة أو الصف أو الفقرة نفسها التي عدّلتها يفتح عرض التعارض (**أبقِ نسختي** / **خذ نسختهم**) كما في تعارضات النص.

## الشعارات والصور الموضوعة بحرية (`overlays`)
قد تحمل الوثيقة `overlays: [{id, kind: "logo"|"image", src, mode, x, y, w, anchor?, caption?}]`. المواضع بالمليمتر وتُطبع في المكان ذاته في PDF وDOCX:
- `mode: "cover"`: من الزاوية العليا اليسرى لصفحة الغلاف.
- `mode: "every"`: في كل صفحة بعد الغلاف (الترويسة والتذييل): x من الحافة اليسرى للصفحة، وy من أعلى مساحة النص.
- `mode: "anchor"`: بجانب كتلة (`anchor` مؤشرها)؛ x من الحافة اليسرى لعمود النص، وy من أعلى الكتلة، وتتحرك معها.
`src` بيانات صورة PNG أو JPEG أعاد المحرر ترميزها عبر لوحة رسم (تُزال البيانات الوصفية، وتُحوّل SVG إلى صورة نقطية، وبحد أقصى 2000 بكسل). العمليات: `insert /overlays/-` و`replace /overlays/<i>` (النقل وتغيير الحجم وتبديل كل الصفحات) و`delete /overlays/<i>`؛ وأول عنصر ينشئ المصفوفة بالعملية `replace /overlays []`. ولا يطبع محرك العرض ولا منشئ DOCX أي `src` ليس من هذا النوع.

## خطافات الويب (`contracts/webhook.schema.json`)
متوقفة افتراضياً وبلا روابط افتراضية. يضيف المستخدم الروابط في لوحة **خطافات الويب**، ويختار الأحداث (الحفظ، وتصدير PDF وDOCX، وتصدير التعديلات، ودمج الاستيراد، وفشل الفحص)، ويمكنه تحديد «تضمين الوثيقة كاملة». الصفحة لا ترسل شيئاً بنفسها: يرسلها الخادم المحلي عبر `POST /api/webhook` (`npm run serve`)، لأن الصفحة المفتوحة من القرص لا تصل إلى أصول أخرى (CORS، وسياسة أمان المحتوى تُبقي `connect-src 'self'`). ولا يمرر الخادم إلا حقول المخطط؛ فلا تُرسل الخطوط ولا علامة الأداة أبداً. وتظهر كل عملية تسليم بحالتها وزمنها، وزر **إرسال تجريبي** يرسل حدث `test`.

## كل شيء قابل للتحرير (0.7.0)
لا شيء مما تطبعه الوثيقة ثابت. كل ذلك في ملف JSON للوثيقة، وينتقل عمليات في ملف التعديلات، ويصل إلى PDF وDOCX (`contracts/edits.schema.json` ← `$defs.documentFields`).

| ماذا | أين يُكتب | كيف |
|---|---|---|
| التسميات الثابتة: عناوين بيانات الضبط، ورؤوس الجداول (سجل المراجعات والأسئلة المفتوحة)، وتسميات القصص، وبادئات التعليقات، والعنوان العلوي، وعلامة السرية | `/labels/<key>` (و`/labels/control/<key>` و`/labels/questionCols/<i>`) | التحرير في المكان، أو قائمة **التسميات** في لوحة التصميم؛ و«طبّق على كل الوثائق» يكتبها في حزمة التصميم (`theme.labels.<locale>`) |
| العنوان والعنوان الفرعي ورمز الغلاف (الشريط الجانبي والترويسة) والإصدار والحالة والتاريخ على الغلاف | `/control/coverTitle` و`/control/subtitle` و`/control/documentId` | التحرير في المكان |
| أسماء الحقول وقيمها (بطاقة الخدمة والمدخلات والمرفقات والحالات) | خلايا الجداول (`…/rows/<r>/<c>`) | التحرير في المكان؛ وإضافة الصفوف وحذفها ونقلها لأعلى ولأسفل |
| التصميم: الألوان حسب الدور، والأحجام، وارتفاع السطر، والهامش الجانبي، وسماكة الخطوط، وتعبئة رأس الجدول ولونه، والتظليل المتناوب | `/design/vars` و`/design/sizes` | لوحة التصميم، مع معاينة حية |
| عنصر واحد فقط | `<block>/style` و`<block>/hidden` | اختر ← **نسّق هذا** أو **إخفاء** |
| أجزاء القالب (الغلاف، وبيانات الضبط، والمراجعات، والمحتويات، والأسئلة المفتوحة): إظهار وإخفاء وترتيب | `/layout/hide` و`/layout/front` | لوحة التصميم |
| الفصول: إخفاء ونقل وتكرار وحذف؛ وإضافة قسم أو جدول | `/chapters/…` | لوحة التصميم |
| CSS متقدم | `/design/css` | لوحة التصميم؛ يُنقّى (بلا `@import` ولا `url()` بعيد ولا تعبيرات)، ويُطبق في المحرر وPDF |

التراجع والإعادة يشملان ذلك كله (فهي عمليات). ويُبلّغ الفحص عن أي تسمية فارغة. والقيمة المستخرجة التي يعدّلها الشخص تُسجل في `/manual`؛ وإعادة الاستخراج تُبقيها وتكتب `harvestConflicts` التي يعرضها المحرر عند الفتح.

## المخططات (0.9.0)

يُحرَّر `model` في كتلة `diagram` (`contracts/diagram.schema.json`) بالعمليات نفسها: يكتب المحرر عملية `replace` **واحدة** على `<block>/model` لكل حركة (نقل، تغيير حجم، إضافة، ربط، نوع، لون، محاذاة، ترتيب، استيراد Mermaid)، ويصل البحث والاستبدال إلى نصوص العقد والأسهم عبر `setText` على `<block>/model/nodes/<i>/label`. المواضع اختيارية: العقدة بلا `x`/`y` يضعها الترتيب التلقائي، والأسهم تُوجَّه من الأشكال، فتحريك شكل يعيد توجيه أسهمه. ومنذ 0.9.1 قد يحمل السهم `via` — نقاط انحناء يضعها المستخدم `[[x, y], …]` بين طرفيه (اسحب مقبض المقطع عرضياً، أو اسحب زاوية، أو «إضافة نقطة انحناء» / «حذف نقطة الانحناء»)؛ ويبقي الموجّه كل مقطع أفقياً أو عمودياً ويضيف زاوية حيث تحرك أحد الطرفين؛ و«مسار تلقائي» يحذف `via`، و«ترتيب تلقائي» يمسح كل `via`. ويجوز أن يحمل النص سطراً جديداً (Shift+Enter أثناء التحرير في المكان). يبقى الإصدار 1: `via` اختياري ولم تتغير أي عملية.

### شريط الأدوات يتبع التحديد

لا تحديد (أو Esc، أو نقرة على الصفحة) ← الأقسام العامة: ملف · إدراج · تحرير · الوثيقة · التصميم · تصدير · العرض. والتحديد يضيف قسماً مميزاً في البداية يحمل اسم المحدد: نص، خلية جدول، صورة، شعار، شكل («شكل: مربع مرحلة»)، سهم، عدة أشكال (محاذاة وتوزيع وتجميع)، مخطط (إضافة أشكال ورموز، ترتيب تلقائي، استعادة، اتجاه، مفتاح، Mermaid). تبقى أربع أدوات ظاهرة والبقية في قائمة «المزيد»، ويبقي تحديد المخطط أيضاً التصغير · الملاءمة · التكبير ظاهرة (و100% في «المزيد»؛ وCtrl مع عجلة الفأرة فوق الرسم يكبّر أيضاً؛ والتكبير حالة عرض لا عملية). ومنذ 0.9.1 تبقى عناوين الأقسام ظاهرة دائماً: إذا ضاق الشريط تُسقط الأدوات العامة كلماتها أولاً، ثم يطوي كل قسم بدوره (الأخير أولاً) أدواته الإضافية في «المزيد» الخاص به، ثم تُسقط أدوات التحديد كلماتها — ولا يتمرر الشريط أفقياً بين 1280 و1920 بكسل. وتسرد لوحة Ctrl+K كل الأوامر تحت التصنيفات نفسها.

### تحرير النص في مكانه (0.9.1)

انقر نقراً مزدوجاً على شكل أو سهم أو نص حر (أو حدده واضغط Enter/F2): يُفتح مربع نص فوق النص نفسه بخط الرسم وحجمه، ويتبع المؤشر اتجاه الكتابة (العربية من اليمين واللاتينية من اليسار). Enter أو النقر خارجه يحفظ (عملية `replace` واحدة)، وShift+Enter سطر جديد، وEsc يلغي. لا نافذة حوار.
