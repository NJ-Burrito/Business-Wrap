# ٠٨ · الاستخراج: مما لدى المستخدم إلى ملف الوثيقة (عربي) — الملف المقابل: 08-harvest.md

طريقان والنتيجة واحدة: الزوج نفسه من ملفات الوثيقة (`document.ar.json` و`document.en.json`) الذي يفتحه المحرر، بالأقسام التي تحتاجها وثيقة المتطلبات. العقود: `contracts/harvest.schema.json` (التمثيل الوسيط للإجراء، وإعدادات المرور، والحصاد الخام).

## أ. من نموذج إجراء
| المدخل | كيف يُقرأ |
|---|---|
| BPMN 2.0 بصيغة XML (تصدير Flowable وCamunda وActiviti) | المسارات والأحواض ← الأطراف؛ `userTask` و`manualTask` ← خطوات ينفذها أشخاص؛ `candidateGroups` و`candidateUsers` و`assignee` ← الطرف عند غياب المسار؛ `formProperty` (مع قيم `value`) و`formKey` ← قاموس بيانات الخطوة؛ البوابات مع `conditionExpression` أو أسماء الروابط ← قواعد القرار؛ المؤقتات الحدّية والوسيطة ← قواعد المهل؛ `subProcess` ← يُسطّح ويُدخل من بدايته ويُخرج من نهاياته؛ `endEvent` ← الحالات النهائية؛ مهام الخدمة والبرمجة والإرسال والاستقبال وقواعد العمل واستدعاء الإجراءات ← خطوات النظام |
| draw.io أو diagrams.net، عادياً أو مضغوطاً | المسارات ← الأطراف؛ المعيّن ← قرار؛ الأشكال البيضاوية ← بداية (بلا مدخل) ونهاية (بلا مخرج)؛ `shape=process` أو الأسطوانة ← خطوة نظام؛ الأسهم وتسمياتها ← الروابط |
| قائمة خطوات YAML أو JSON | `process` و`actors` و`steps` (`name` مع `actor` و`next`، أو `decision` مع `options` أو `yes` و`no`، و`fields` اختيارياً، و`timer: {after, to}`، و`system: true`) و`ends` |

يبني المحلل **التمثيل الوسيط للإجراء** ويحفظه في الوثيقة (`process`)، لتعيد لوحة **الإجراء** في المحرر رسم السير و**إعادة بناء الأقسام** لاحقاً.

**المخطط يعرض خطوات الأشخاص فقط.** تُطوى خطوات النظام: السهم الخارج من خطوة شخص مروراً بأي عدد من خطوات النظام يصل إلى خطوة الشخص التالية أو القرار التالي، مع أول تسمية يمر بها. مسار لكل طرف، وأعمدة بحسب الترتيب، والقرارات معيّنات، والمهل بخط متقطع. وتُعكس صورة المخطط في الوثائق العربية.

الأقسام المكتوبة: المقدمة (مع ذكر المصدر) · الأطراف والأدوار · مخطط سير العمل · الخطوات (الخطوة، الطرف، تنتقل إلى) · قواعد العمل (القرارات والمهل) · قصص المستخدمين (قصة لكل خطوة شخص، مع جدول الإجراءات وقاموس البيانات) · حالات الطلب · أسئلة مفتوحة لما لا يذكره النموذج (خطوة بلا طرف، أو غياب حدث النهاية). تبقى الأسماء كما وردت في المصدر: النموذج المكتوب بلغة واحدة يعطي النسختين الأسماء نفسها، مع تسميات الأقسام بلغة كل نسخة.

## ب. المرور على الخدمة الفعلية واستخراجها
يمر متصفح Chrome حقيقي (ظاهر افتراضياً) على الخدمة كما يفعل الشخص:
١. يُقرأ robots.txt أولاً، وصفحة البداية الممنوعة توقف المرور (`respectRobots: false` يتجاوز ذلك عن قصد).
٢. بطاقة الخدمة: العنوان والفقرات وأزواج البند والقيمة (`dl` والجداول ذات العمودين).
٣. تسجيل الدخول، إما في البداية أو عند ظهور نموذجه؛ والقيم من `$env:NAME` أو `$secret:key` (الملف المستثنى من git `.local/harvest-secrets.json`). ولا تُكتب القيم المُدخلة في الحصاد ولا في السجل ولا في اسم ملف.
٤. **التوقف للإنسان** (الرمز المؤقت أو التحقق البشري): ينتظر المرور حتى يختفي العنصر (أو يظهر عنصر آخر) ثم يكمل.
٥. كل خطوة نموذج: كل حقل ظاهر بتسميته كما يقرؤها المستخدم، ونوعه، وكونه إلزامياً، وخيارات القوائم وأزرار الاختيار، وحقول الملفات مع الأنواع المقبولة؛ ولكل خيار، الحقول المخفية التي يُظهرها (الحقول المشروطة)؛ ومحاولة فارغة لجمع رسائل التحقق (رسائل الموقع أولاً، ورسائل المتصفح فقط إن لم يُظهر الموقع شيئاً)؛ ثم قيم نموذجية محايدة ثم «التالي».
٦. بعد الإرسال: عنوان الصفحة وقائمة الحالات.
٧. تبويب واحد، ولوحة المفاتيح أولاً (التركيز ثم Enter أو Space، والنقر فقط إن لم يحدث شيء)، ومهلة بين الإجراءات (`delayMs`)، ولقطات بحجم الشاشة فقط لكل مرحلة.
٨. اللغتان معاً حين تعطي الإعدادات صفحة بداية لكل منهما.

المخرج الخام: `harvest.json` واللقطات. الأقسام المكتوبة: المقدمة · بطاقة الخدمة · المدخلات (قسم لكل خطوة نموذج: التسمية، النوع، إلزامي، الخيارات، يظهر عند) · المرفقات · رسائل التحقق · قصص المستخدمين (قصة لكل خطوة نموذج) · حالات الطلب.

## في المحرر
**وثيقة جديدة** (زر في الشريط أو `Ctrl+K`): *من نموذج إجراء* يقرأ الملف داخل الصفحة؛ و*المرور على الخدمة الفعلية* يحتاج `npm run serve` لأنه يشغّل متصفحاً على هذا الجهاز. وتُفتح الخدمة الجديدة فوراً بنسختيها.
لوحة **الإجراء**: أضف الأطراف والخطوات والقرارات والحالات النهائية، واربطها، وشاهد المخطط، ثم **أعد بناء الأقسام** (في النسختين؛ ويبقى ضبط الوثيقة والمراجعات والشعارات الموضوعة).

## MCP
`harvest_model {model, out_dir, name?}` و`harvest_crawl {config, out_dir}` تعيدان مساري ملفي الوثيقة ومسار المحرر.
