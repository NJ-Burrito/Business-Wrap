01

الأدلة، ثم المحرر، ثم PDF وDOCX

  1. 1.1

    الأدلة

    نموذج الإجراء يعطي الأدوار وسير العمل والقواعد والحالات. والجولة في الخدمة الحية تعطي البطاقة والنموذج والمرفقات والرسائل. والدمج يحتفظ بالاثنين.

  2. 1.2

    المحرر

    ملف HTML واحد. الصفحة التي تحررها هي الصفحة التي تطبع. كل تغيير مسجل ويمكن التراجع عنه.

  3. 1.3

    PDF وDOCX

    النسختان معا، والخطوط مضمنة نصا حقيقيا قابلا للتحديد. ومعهما ملف التعديلات وحزمة التصميم.

02

ما تحصل عليه

F-01

طريقان للدخول

ابدأ من BPMN أو draw.io أو YAML، أو من جولة في الخدمة الحية.

F-02

الصفحة هي المطبوعة

كل كلمة مطبوعة وكل جدول وعنوان قابل للتعديل في مكانه.

F-03

اللغتان بالمنزلة نفسها

النسخة العربية والإنجليزية جنبا إلى جنب. والتخطيط لا ينقلب.

F-04

مخططات قابلة للتعديل

أشكال وأسهم بانحناءات ونصوص في مكانها. واستيراد Mermaid وتصديره.

F-05

أي خط، نصا حقيقيا

خطوط المشروع أو خطوط جهازك أو ملف ترفعه، مضمنة في PDF وDOCX.

F-06

أدوات تشرح نفسها

توقف على أداة: تظهر بطاقة باسمها واختصارها وحركة تبين عملها.

F-07

ست حزم قوالب

الخدمة الإلكترونية والتجارة الإلكترونية ومركز الاتصال والموافقات وSaaS وIEEE 29148 العامة، وحزمتك أنت.

F-08

المسح يتوقف قبل الإرسال

المسح تشغيل تجريبي. ولا يقدم طلب حقيقي إلا بمفتاحين صريحين.

F-09

فحص أمني على كل إيداع

محتوى العملاء وبيانات الدخول والمسارات المحلية تبقى خارج المستودع.

F-10

لوكيل الذكاء الاصطناعي

إضافة Claude Code وخادم MCP محلي: بناء وتحرير وتصدير وحصاد.

03

اختر طريقة واحدة

الطرق الثلاث تعمل على جهازك.

الأسهل

إضافة Claude Code

المهارة وخادم MCP معا.

/plugin marketplace add NJ-Burrito/Business-Wrap
/plugin install business-wrap@business-wrap

ثم قل: «ابن وثيقة متطلبات …» أو «افتحها في المحرر».

أي عميل MCP

خادم MCP

سطر واحد: الإصدار 0.13.1 من وسم GitHub، فسجل npm ما زال على 0.12.0. يحتاج Node 20 أو أحدث.

claude mcp add business-wrap -- npx -y -p github:NJ-Burrito/Business-Wrap#v0.13.1 business-wrap-mcp

من نسخة المستودع (بلا npm ci): وجه العميل إلى node <path>/Business-Wrap/mcp/cli.mjs.

بلا وكيل

من المصدر

ابن الوثيقة النموذجية وافتحها في المحرر.

git clone https://github.com/NJ-Burrito/Business-Wrap
cd Business-Wrap
npm ci
npm run sample
npm run serve

يفتح على http://127.0.0.1:4317/ مع تصدير PDF وDOCX بنقرة واحدة. Chrome أو Edge لملفات PDF، وuv لملفات DOCX.

05

هل هو آمن؟

  • على جهازك فقط

    المحرر وطابعة PDF ومنشئ DOCX تعمل على جهازك. لا يرفع أي شيء.

  • مرة في اليوم

    الطلب التلقائي الوحيد هو فحص التحديث، إلى قائمة الإصدارات العامة على GitHub، بلا حساب. أوقفه من الإعدادات أو بالأمر node update/cli.mjs --off.

  • تشغيل تجريبي

    المسح يتوقف قبل الإرسال أو التقديم أو التأكيد أو الدفع. وتقديم طلب حقيقي يحتاج submit: true و--yes-file-real-request.

  • كل إيداع

    فحص أمني يبقي محتوى العملاء وبيانات الدخول والمسارات المحلية خارج المستودع.

06

إجابات قصيرة

هل هو مجاني؟

نعم. رخصة MIT، بلا خطة مدفوعة وبلا حساب.

هل تغادر وثيقتي جهازي؟

لا. المحرر وطابعة PDF ومنشئ DOCX تعمل كلها على جهازك.

الطلب التلقائي الوحيد هو فحص التحديث: مرة في اليوم على الأكثر، إلى قائمة الإصدارات العامة على GitHub. وخطافات الويب ترسل فقط إلى عنوان تحدده أنت.

هل أحتاج Claude؟

لا. المحرر وسطر الأوامر يعملان وحدهما. والإضافة وخادم MCP اختياريان.

ماذا يدخل وماذا يخرج؟

يدخل: نموذج إجراء (BPMN أو draw.io أو YAML) أو مسح لخدمة حية.

يخرج: PDF وDOCX وملف التعديلات JSON وحزمة التصميم والمحرر محفوظا بصيغة HTML.

هل يقدم المسح طلبا حقيقيا؟

لا، إلا إذا طلبت ذلك مرتين: submit: true في الإعدادات و--yes-file-real-request. وإلا توقف قبل الإرسال أو التقديم أو التأكيد أو الدفع.

أي الخطوط أستخدم؟

ثمانية افتراضيا: نسختك أنت لها الأولوية، ونسخة احتياطية مضمنة (تحت رخصة ثمانية لا MIT) تطبع PDF صحيحا من أول مرة. ويعمل أيضا أي خط على جهازك أو ملف ترفعه، وترخيصه مسؤوليتك.

على أي نظام يعمل؟

جرب على Windows 11 مع Node 24 وChrome. ويحتاج Node 20 أو أحدث، وChrome أو Edge، وPython مع uv لملفات DOCX. ولم يجرب على macOS ولينكس.
