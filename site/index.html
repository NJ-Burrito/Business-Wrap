01

Evidence, then the editor, then PDF and DOCX

  1. 1.1

    Evidence

    A process model gives roles, workflow, rules and statuses. A walk through the live service gives the card, the form, attachments and messages. The merge keeps both.

  2. 1.2

    Editor

    One HTML file. The page you edit is the page that prints. Every change is recorded and can be undone.

  3. 1.3

    PDF + DOCX

    Both editions, with the fonts embedded as real, selectable text. Plus the edits file and a design pack.

03

Pick one way in

All three run on your computer.

Easiest

Claude Code plugin

The skill and the MCP server together.

/plugin marketplace add NJ-Burrito/Business-Wrap
/plugin install business-wrap@business-wrap

Then say "build the requirements document for …" or "open it in the editor".

Any MCP client

MCP server

One line: 0.15.1 from the GitHub tag (npm still serves 0.12.0). Needs Node 20+.

claude mcp add business-wrap -- npx -y -p github:NJ-Burrito/Business-Wrap#v0.15.1 business-wrap-mcp

From a clone (no npm ci needed): point your client at node <path>/Business-Wrap/mcp/cli.mjs.

No agent

From source

Build the sample and open it in the editor.

git clone https://github.com/NJ-Burrito/Business-Wrap
cd Business-Wrap
npm ci
npm run sample
npm run serve

Opens on http://127.0.0.1:4317/ with one-click PDF + DOCX. Chrome or Edge for the PDF, uv for the DOCX.

05

Is it safe?

  • Local only

    The editor, the PDF printer and the DOCX builder run on your computer. Nothing is uploaded.

  • Once a day

    The one automatic request is the update check, to the public GitHub release list, with no account. Switch it off in Settings or with node update/cli.mjs --off.

  • Dry run

    The crawler stops before Send, Submit, Confirm or Pay. Filing a real request needs submit: true and --yes-file-real-request.

  • Every commit

    A security gate keeps client content, credentials and local paths out of the repository.

06

Short answers

Is it free?

Yes. MIT licence, no paid plan, no account.

Does my document leave my computer?

No. The editor, the PDF printer and the DOCX builder run locally.

The one automatic request is the update check: at most once a day, to the public GitHub release list. Webhooks send only to an address you set.

Do I need Claude?

No. The editor and the command line work on their own. The plugin and the MCP server are optional.

What goes in, what comes out?

In: a process model (BPMN, draw.io, YAML) or a crawl of a live service.

Out: PDF, DOCX, the edits JSON, a design pack, and the editor saved as HTML.

Will the crawler file a real request?

Not unless you ask twice: submit: true in the config and --yes-file-real-request. Otherwise it stops before Send, Submit, Confirm or Pay.

Which fonts can I use?

Thmanyah by default: your own copy wins, and a bundled fallback (under the Thmanyah licence, not MIT) makes the PDF right out of the box. Any font on your computer, or a file you upload, also works; its licence is your responsibility.

What does it run on?

Tested on Windows 11 with Node 24 and Chrome. It needs Node 20+, Chrome or Edge, and Python with uv for DOCX. macOS and Linux are untested.
